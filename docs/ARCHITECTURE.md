# المعمارية

## الطبقات

```
Pages / Components            (React + framer-motion + SVG)
        │  useData() / useActions()
DataProvider ── اشتراكات حيّة ── Store (واجهة موحّدة)
        │                          ├─ FirestoreStore  (companies/{id}/…، تخزين دائم للعمل دون إنترنت)
        │                          └─ LocalStore      (localStorage — وضع العرض التجريبي)
actions.ts  عمليات محاسبية ذرّية (writeBatch + increment)
lib/*       منطق نقي بلا تبعيات واجهة: pricing · aging · credit · ledger · messages · whatsapp
```

`Store` يعرّف: `subscribe` (حيّ)، `batch()` (set/merge/update/remove + increment/delete)، ومزامنة معلّقة. التنفيذان متطابقان السلوك، بما فيه **رفض المخزون السالب بذرّية** (يُسترجع كل شيء) — وهذا مغطّى باختبارات.

## نموذج البيانات (Firestore)

```
users/{uid}                    { name, email, role, companyId, repId? }
invites/{emailLowercase}       { companyId, role, name, repId? }
companies/{companyId}          { name, currency, dialCode, defaultCreditDays, ownerUid }
  customers/{id}               { name, zoneId, repId, priceList, creditLimit, creditDays, balance, … }
  products/{id}                { prices{wholesale,semi,retail}, cost, minStock, … }
  warehouses/{id}              { type: main|branch|van, repId? }
  stock/{warehouseId_productId}{ qty }                       ← لا يقل عن صفر (قواعد)
  stockMovements/{id}          { type, qty, refId }          ← إضافة فقط
  orders/{id}                  { items[], total, status, paymentType, dueAt, repId, … }
  collections/{id}             { amount, method, orderId?, status: active|void }
  offers · zones · reps · visits
```

الرصيد `customers.balance` مُخزَّن (denormalized) لقراءة سريعة، ويحقق دائمًا:

```
balance = Σ(إجمالي الطلبات غير الملغاة) − Σ(السندات الفعّالة)
```

وهذا اللامتغيّر يُختبر على بيانات البذرة، وكل عملية (إنشاء/إلغاء طلب، تحصيل، إلغاء سند) تحافظ عليه.

## تدفقات رئيسية

**إنشاء طلب** (دفعة ذرّية واحدة): مستند الطلب + خصم المخزون لكل سطر (`merge + increment(-qty)`، الكمية = المدفوع + المجاني) + حركات المخزون + `customer.balance += total − paid` + سند دفعة مرتبط إن وُجد دفع (البيع النقدي = دفع كامل). إن تجاوز الدين الحد الائتماني: المندوب ← حالة `credit_hold` (المخزون محجوز، والمدير يوافق أو يرفض)، والمدير ← يُعتمد مباشرة.

**إلغاء طلب**: يعيد المخزون، ويبطل الدفعات المرتبطة، ويعكس القيد: `balance += −total + paid`.

**التسعير**: لكل سطر أفضل عرض واحد للعميل (خصم نسبة أو اشترِ X واحصل على Y)، ثم أفضل عرض على الفاتورة بعد خصومات الأصناف. بلا تراكم عروض الأصناف لتبقى النتيجة متوقعة وشفافة.

**أعمار الديون**: الدفعات المرتبطة بطلب تُخصم من ذلك الطلب (حتى لا تُخفي دفعة نقدية حديثة فاتورة آجلة قديمة)، وسندات القبض العامة تُسدِّد الأقدم أولًا (FIFO)، وما زاد من الرصيد المسجَّل على المتبقي المحسوب (طلبات أقدم من النافذة المحمّلة) يُضاف لأقدم شريحة.

## العمل دون إنترنت والمزامنة

- Firestore `persistentLocalCache` + `persistentMultipleTabManager`: القراءة والكتابة تعمل دون اتصال وتُرفع تلقائيًا.
- PWA (`vite-plugin-pwa`) تخزّن الهيكل والخطوط؛ مُتحقَّق من إعادة التحميل دون شبكة.
- أرقام الطلبات `yyMMdd-XXX` (تاريخ + عشوائي) لأن العدّاد المركزي يتعارض مع المزامنة بعد الانقطاع.
- شريحة «متزامن / جارٍ المزامنة / دون اتصال» تعتمد `hasPendingWrites` وحالة الشبكة.

## الأمان

- عزل كامل لكل شركة بمسار `companies/{companyId}`؛ الدور يُقرأ من `users/{uid}` (لا يعدّله صاحبه).
- **تسجيل الشركة**: `getAfter()` يتحقق في الدفعة نفسها أن المستخدم هو `ownerUid` للشركة الجديدة، ولا يمكن الاستيلاء على شركة موجودة.
- **الدعوات**: المفتاح البريد بحروف صغيرة؛ الانضمام يشترط `email_verified` ومطابقة الدور والشركة والمندوب تمامًا لما في الدعوة (يمنع انتحال بريد مدعوّ).
- المندوب يقرأ/يُنشئ طلباته وتحصيلاته وزياراته فقط، ولا يعدّل حدًا ائتمانيًا ولا يحذف شيئًا؛ وعميله الجديد يبدأ بحد صفر.
- المخزون ≥ 0 دائمًا، وحركات المخزون والسجلات المالية غير قابلة للحذف.
- الاختبار: `rules-tests/` (30 اختبارًا على المحاكي).

**تنازلات واعية**
1. دور المستخدم يُقرأ بـ `get()` في القواعد: قراءة إضافية مفوترة لكل طلب. البديل الأرخص: **Custom Claims** عبر Admin SDK/Cloud Function.
2. الترحيل (الرصيد/المخزون) من العميل. المهاجم الذي يملك صلاحية «مندوب» قد يعدّل أرصدة (محصورة بحقل `balance`). لإغلاق ذلك: Cloud Function تستمع لإنشاء الطلب/السند وتحدّث الأرصدة، وتُمنع الكتابة المباشرة من العميل.
3. الطوابع الزمنية من جهاز المستخدم (`serverTimestamp` يعقّد العمل دون إنترنت والترتيب المحلي).

## الأداء والحجم

- تحميل كسول لكل صفحة؛ حزم منفصلة: تطبيق ~31KB، motion ~48KB، react ~80KB، firebase ~184KB (gzip).
- اشتراك واحد لكل مجموعة بدل استعلامات متفرقة؛ الأرقام المشتقة في الذاكرة (`useMemo`).
- الحدود: 1500 طلب / 1500 سند / 800 زيارة / 400 حركة مخزون. للأحجام الأكبر: تجميعات يومية بـ Cloud Functions.
- Firebase SDK يُحمَّل حتى في الوضع التجريبي (تنازل عن تعقيد التحميل الكسول).
